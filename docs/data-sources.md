# 数据来源与自动同步

默认统计来源是 [AramHex 数据仓库](https://github.com/czgreat/aramhex-data)，使用国服海克斯大乱斗的全体样本、常规规则。只统计来源采集到的有效对局，不代表全服；持有海克斯与获胜是相关关系，不代表因果。

## 自动同步

- 内置一份经过文件大小与 SHA-256 校验的完整快照，首次启动即可离线使用。
- 每次启动检查 `latest.json`，运行期间每 6 小时检查；失败后每 15 分钟重试。
- 优先直连原作者官方数据镜像 `https://aramhex.com/u/data`，失败后沿用系统代理访问官网，再尝试 GitHub 与 jsDelivr 的 Fastly、Gcore 镜像。直连仅用于公开统计下载，不修改系统代理配置。每个候选清单或数据文件均校验，镜像返回错误内容时继续换源。
- 更新序号或文件内容变化时下载英雄榜、英雄×海克斯统计、海克斯目录与统计说明。官网镜像按清单路径下载；GitHub/CDN 使用固定的 `data-v<seq>` 标签。所有通道逐项验证清单声明的文件长度、SHA-256、字段、版本及引用完整性，镜像在下载期间更新造成文件不一致时不入库。
- 全部文件成功校验后以一个 SQLite 事务切换英雄榜与海克斯统计，失败时保留上次完整缓存；不回退到较旧的更新序号。同步失败时设置页显示「使用缓存」。
- 设置页显示的是数据源的快照时间，不是本机检查时间。无更新时只检查清单，不重新下载数据；应用关闭期间不在后台同步，下次启动检查。
- 不再自动请求 OP.GG，也不上传截图、玩家信息或对局记录。现有画面检测和 OCR 路径不变。

## 英雄 1–5 档

AramHex 提供英雄胜率名次，但没有 OP.GG 的 1–5 档位。浮层数字为本应用按胜率名次划分的五档：每 20% 一档，1 档最高、5 档最低，公式为 `floor((名次 - 1) × 5 / 英雄总数) + 1`。173 位英雄时为 1–35、36–70、71–104、105–139、140–173；例如 60/173 显示 2 档。这不是官方评级，也不是玩家段位。读取现有缓存时计算，无需等待来源更新。其他来源已有的档位按原值保留。

## 本应用 S/A/B 评级

来源的原始胜率、局数直接展示；S/A/B 是本应用按以下规则计算的评级，不是 AramHex 或腾讯官方等级：

`平滑胜率 = (胜场 + 该英雄平均胜率 × 300) / (局数 + 300)`

`提升百分点 = (平滑胜率 − 该英雄平均胜率) × 100`

- S：提升至少 2 个百分点，建议「优先考虑」。
- A：提升在 0 至 2 个百分点之间，建议「可以选择」。
- B：低于英雄平均胜率，建议「收益偏低，可考虑刷新」。
- 来源 `low_sample` 为真或不足 1000 局时提示「样本偏少，仅供参考」，不作强推荐；等级仍为平滑后的统计参考。
- 不同稀有度仍分别以当前英雄平均胜率为基准，不声称是同稀有度内的官方排名。
- 来源剔除的海克斯不评级、不显示可靠胜率；目录中存在但当前英雄没有统计时显示「暂无可靠数据」，不硬判为 B。内部标记 3176 不显示。
- 建议来自统计规则，不生成未经验证的玩法、装备联动或因果结论。

## 旧版手动导入

设置页继续支持原有英雄榜及 S/A/B JSON 导入，格式见 [英雄榜 schema](../data/schemas/rank-snapshot.schema.json) 与 [海克斯 schema](../data/schemas/augment-grade-snapshot.schema.json)。旧格式不包含胜率；手动导入后按其实际来源展示，不将 AramHex 胜率套用到旧评级。新的来源快照到来时自动同步会替换手动快照。

旧的 `data/seed/augment_grades.json` 目前用于提供既有英文英雄 ID 与中文称号的对应关系，并保留旧格式兼容。它的序位分级不是新的推荐来源。
