# OP.GG 启动数据刷新设计

日期：2026-10-30

## 目标

以 OP.GG 派生公开静态数据作为当前海克斯推荐来源。英雄榜只保存并显示名次（如 `1/173`）和来源实际提供的段位徽章；不保存或显示胜率。海克斯按英雄展示 S/A/B 标签及简短理由。

## 现状

应用已有 SQLite 快照、JSON 导入和空数据提示，但没有生产榜单或海克斯快照，也没有在线数据提供方，所以当前页面为空。现有数据层可保留作为缓存和导入兜底。

## 方案

- **直接自动抓取 OP.GG：**正常页面没有可读取的榜单数据，参考项目需要 Selenium 浏览器抓取；同时 OP.GG 当前使用条款禁止自动脚本抓取，因此不采用。
- **本地静态快照（采用）：**首次启动时将随应用打包的英雄海克斯快照导入 SQLite；之后读取本机缓存，不联网、不覆盖用户已导入数据。快照来源是参考项目公开的 OP.GG 派生 CSV。
- **手动 JSON 更新：**保留现有导入作为用户以后替换静态海克斯数据和导入英雄榜的方式。

## 刷新行为

1. 应用启动时从本机 SQLite 显示最后一次成功保存的数据。
2. 若海克斯表为空，导入内置的静态 JSON 快照；已有用户数据不覆盖。
3. 快照内每位英雄的前 10 名海克斯标为 S、11–35 名标为 A、其余标为 B。理由说明该推荐在该英雄的快照序位，不暴露胜率。
4. 静态文件不包含英雄榜，因此英雄名次和段位徽章不生成；页面可搜索英雄并进入海克斯推荐。
5. 游戏内推荐只读本机缓存，不联网。设置页保留 JSON 导入，并标注快照来源与补丁未核实状态。

## 范围与限制

不加入胜率展示、游戏操作自动化或 AI 生成榜单。不给 OP.GG 页面发送账号信息，不使用私有账号接口，不绕过访问限制，也不直接自动抓取 OP.GG。

OP.GG 帮助页建议注明来源且避免影响服务；当前使用条款禁止通过自动脚本抓取。因此当前版本使用参考仓库提供的静态数据，自动 OP.GG 刷新暂不实现。CSV 未声明补丁和原始更新时间，界面必须标记补丁未核实及本地快照生成时间。
